## 本版变化（相对 1.2.0）

- 保留原有 193 个频道的位置，修正同台异名，新增 60 个频道或特色直播条目；合并后 **253 个列表项、485 条候选线路**。景观直播、影视轮播单独分组，列表项数量不等同于传统电视台数量。
- 加入六个公开候选订阅，与原有五个订阅共同补充当前频道的线路。本轮电脑严格筛选得到 **97 个条目、118 条合格线路**，优先放入随包候选；旧频道没有新合格线路时保留原地址供尝试，不标为合格。
- 修正 CGTN“纪录/记录”重复，区分 CCTV5 / CCTV5+、CCTV4K / CCTV4，以及 CCTV4 欧洲版 / 美洲版。经过画面核对的 TVBS 新闻地址只按该 URL 更名，不把所有 TVBS 都合并为新闻台。
- 排除本轮确认的五条“NO SIGNAL”占位地址；这是一份已知地址排除表，并非能识别任意占位、广告或错误节目内容的通用识别器。
- 保留每频道 12 小时有效期、断点续测、前台检测、同台候选比选与失败提示。覆盖安装不自动启动应用。

本轮有合格的 CCTV1 和 CCTV5+；**CCTV5、CCTV6 没有通过本轮严格筛选**，仍保留频道位置供后续更新和手动尝试，不能声称已修复这两个频道的源站。

## 巡检怎样运行

每次进入前台是一个检查点，并非每次重新测全部频道。频道完整比选结束后，成功或失败记录均保存 12 小时；有效期内跳过。未完成的检测没有完成时间，下次继续已保存的分片和轮次。只在应用前台运行，离开前台暂停，不设后台检测服务或定时唤醒。

HLS 每条线路两轮、每轮四个不同的完整分片；计算每段“媒体秒数 ÷ 完整下载秒数”，最差值须 **≥1.5**，并通过至少 **30 帧实际视频解码**。不是仅测 HTTP 200、首字节、QPS 或少量 Range 数据。对当前纳入的同台候选（最多 12 条）都完成比较后，选最差速度余量最大的一个；相同则选最慢分片耗时更短的一个。

电脑样本不会伪装成盒子的巡检记录。电脑与盒子可能有不同的 DNS、线路和解码能力；盒子自行测量后才产生本机的 12 小时记录。网络变化或签名过期仍可能使已通过的源失效。自动巡检在选台播放时暂停，手动巡检可以继续播放并降为单路检测，仍可能占用网络带宽。

详细的边界、缓存、失败回退、支持格式和电脑/盒子差异见 [规则说明](docs/SOURCE_RULES.md)。

## 下载与遥控器

从 [Releases](https://github.com/suqianqiu/qianqiu-live/releases/latest) 下载 `QianqiuLive-1.3.0.apk`，使用 U 盘或已授权的网络 ADB 覆盖安装。升级应保留原签名；自行构建的签名与发布版不同，不能直接覆盖。源码 ZIP 不包含发行私钥。

| 按键 | 操作 |
| --- | --- |
| 确定 | 显示频道列表 / 选择播放 |
| 上、下 | 全屏播放时切换频道；失败时仍可继续切换 |
| 返回 | 返回列表 / 在未播放时退出 |
| 左、右 | 全屏时选择解码方式 |
| 菜单 | 导入列表、恢复随包列表、手动巡检、自动检查开关等设置 |
| HOME | 离开前台、停止播放并暂停巡检 |

失败时显示“该电视台无法播放，请继续点击↑或↓，或Back返回”，不自动跳回列表；播放组件调用异常会被捕获并显示提示，自动解码策略仅尝试一次软解。连续遥控事件有节流及异步播放器释放，减少事件堆积。

## 构建

需要 JDK 21、Android SDK platform 35、build-tools 35.0.0、PowerShell 7。按 `tools/dependencies.json` 下载并核验官方 LibVLC 依赖，然后执行 `pwsh -File build.ps1`。构建脚本在本地生成测试签名，发行私钥不入库。指定自己有权操作的设备后才能用 `-Install -Device DEVICE_IP:PORT -AdbPort PORT` 安装；安装不自动启动应用。
